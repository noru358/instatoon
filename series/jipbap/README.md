# 집밥 콘텐츠 기획·제작 설계

버전: 0.1 / 작성: 2026-09-06 / 상태: 사용자 검토용 설계 초안

현재 위치와 승인 기록은 [STATE.json](STATE.json), 첫 회차의 대사·컷·시간 정보는
[episodes/HB001/EPISODE_DESIGN.json](episodes/HB001/EPISODE_DESIGN.json)이 단독 소유한다.
이 문서는 시리즈의 기획·공정·데이터 계약을 소유한다. 설계 완료는 사용자 승인이나 작화 검증 통과가 아니다.

## 1. 제작 목적과 시청 경험

**짧은 시간 동안 한 끼를 같이 먹는 감상툰.**
음식의 첫인상 → 한입의 식감 → 먹는 방법에 따른 변화 → 다음 입으로 이어지는 만족을 보여준다.
집밥의 평범함 안에서 구체적인 맛과 행동을 발견한다. 세계관을 설명하지 않아도 첫 화면에서 먹고 싶은 음식이 보여야 한다.

- 1차 시청자 가설: 익숙한 한국 집밥을 좋아하고, 휴대폰에서 짧게 음식 구경·대리 식사를 즐기는 사람.
- 첫 표현 언어: 한국어. 소리 없이도 음식과 행동을 읽을 수 있게 구성한다.
- 시리즈 가칭: **집밥 한입**. 공개 채널명·계정 개설은 아직 결정하지 않았다.
- 한 편의 약속: 음식 하나, 그 음식만의 감각, 자연스러운 먹는 행동, 짧은 감상.
- 서사 엔진: 큰 사건 대신 음식 상태·먹는 조합·반응이 바뀐다. 반전이나 교훈은 필수가 아니다.
- 재방문 이유 가설: 다음에는 무슨 집밥을 어떤 방식으로 먹을지 궁금함, 그림의 식욕 자극, 익숙한 취향의 발견.

범위는 가정에서 먹는 밥·국·반찬·간단한 한 그릇을 중심으로 한다.
조리는 식감 이해에 꼭 필요한 한 동작이 있을 때만 짧게 넣는다.
레시피 단계·영양 설명·식당 순위·과한 먹방·가족 신파를 기본 구성에 추가하지 않는다.
사용자가 이후 요청하면 별도 형식으로 검토한다.

## 2. 리포와 작업 분리 결정

지금은 **noru358/instatoon 안의 series/jipbap/**가 시리즈 경계이고,
**design/jipbap-series**는 이번 설계를 검토하는 임시 작업 브랜치다.

| 선택 | 현재 판단 | 이유 |
|---|---|---|
| 새 리포 | 당장은 만들지 않음 | 참조 전달·작화 검수·레터링 등 재사용할 공정이 많고, 별도 권한·팀 요구가 아직 없음 |
| 같은 리포의 시리즈 폴더 | 채택 | 기획·상태·레퍼런스·산출물을 별도 경로로 관리하면서 공통 코드 변경을 추적할 수 있음 |
| 작업 브랜치 | 이번 설계에 채택 | E007과 동시 작업을 분리하고 초안 diff를 검토 가능하게 함 |
| 브랜치를 영구 채널로 운영 | 채택하지 않음 | 공통 수정이 장기간 서로 달라지는 문제를 막기 위해 승인·통합 후 폴더 경계로 운영 |

공통 엔진을 물리적으로 분리하거나 AutoPipeline 구조를 재편하는 작업은 첫 시안 검증 후 필요할 때 한다.
독립 운영 팀·접근 권한·배포 주기·자산 규모가 생기거나 생산 공정이 크게 달라질 때 별도 리포를 검토한다.
이번 브랜치는 기본 운영 버전이 아니므로 상위 AutoPipeline의 자식 포인터를 이 초안으로 변경하지 않는다.

| 영역 | 재사용 원칙 | 집밥에서 설계하는 차이 |
|---|---|---|
| 소재 | 실제 사람이 남긴 구체적 관찰과 출처 구분 | 음식·식감·먹는 습관이 소재. 인터넷 사건·갈등·반전 수집을 필수로 두지 않음 |
| 대사 | 말맛과 구체성, 사전 검수 | 짧은 속말·나레이션. 무대사가 더 좋으면 생략 |
| 콘티 | 전체 계획 선행, 한 컷 한 역할 | 음식 상태와 식기 이동이 인과관계. 음식 중심 컷과 반응 컷 배분 |
| 그림체 | 승인 시각 참조가 우선, 실제 미디어 전달 | 집밥용 스타일은 미확정. 기존 v2는 후보이며 자동 상속·확정하지 않음 |
| 구도·표정 | 장면 의도에 맞는 변주·정체성 유지 | 음식 접사, 손 시점, 좌우 측면 등을 목적에 맞게 선택. 방향별 컷 수 할당은 하지 않음 |
| 파일 | 한 컷=한 무문자 이미지, 대사 별도 | 그림 원본을 캐러셀/영상에서 각 레이아웃에 맞춰 재사용 |
| 승인 | 첫 컷 승인 후 나머지 내부 QC, 전체 작화 승인 | 이 구조를 채택. 컷마다 사용자 승인 요구하지 않음 |
| 수정 | 마지막 정상 산출물에서 국소 수정 | 음식량·식기 위치의 수정은 연결된 컷도 영향 검토 |
| 품질 | 계약 오류와 취향 판단을 구분 | 식욕·식감·감상의 구체성을 집밥 고유 기준으로 평가 |
| 성과 | 실제 결과를 기록해 다음 기획에 반영 | 저장·완독·음식별 반응을 참고하되 인기 메뉴 하나로 자동 수렴시키지 않음 |

기존 루트 MASTER_PROMPTS의 일괄 무질감·배경보다 인물 디테일 우선 규칙은
음식 중심 시리즈의 실험안과 충돌할 수 있다. 두 문서를 합쳐서 생성기에 넣지 않는다.
기존 썰 인스타툰의 승인 규칙을 덮어쓰는 변경도 하지 않는다.
집밥의 음식 표현 허용 범위는 실제 시안 검증 후 이 시리즈의 스타일로 승격한다.

## 4. 포맷과 회차 구성

파일 수·시간은 시험 시작값이며 매회 할당량이 아니다.

| 결과물 | 기본 설계 | 현재 순서 |
|---|---|---|
| 캐러셀 | 4:5, 1080×1350, 대체로 4–6컷, 한 컷 한 파일 | 먼저 음식 작화와 감상 호흡을 검증 |
| 가벼운 나레이션 애니메이션 | 9:16, 1080×1920, 대체로 20–35초 | 통과한 작화를 바탕으로 후속 시험 |
| 원본 | 무문자 작화 + 편집 가능한 글자 + 소리·타임라인 자료 | 결과물과 함께 관리 |

기본 감각 흐름은 `한 상/음식 → 첫입 준비 → 첫입 → 조합 또는 식감 변화 → 여운`이다.
음식에 따라 한 단계 생략·순서 조정 가능. 실제 먹는 과정이 자연스러운지가 우선이다.
표지용 별도 타이틀 카드로 음식 노출을 늦추지 않는다.
영상은 무조건 모든 정지 컷을 같은 길이로 배열하지 않는다.

캐러셀에서 영상으로 바꿀 때는 중심 음식·입·손·자막 영역을 재배치한다.
4:5 그림을 9:16으로 늘이거나 기계적으로 잘라 손/그릇이 사라지게 하지 않는다.
단순 배경 확장과 위치 이동으로 해결되면 재사용하고, 의미가 손상될 때만 필요한 장면을 다시 제작한다.

## 5. 소재 공급과 초기 메뉴 설계

소재 카드에 음식 이름만 기록하지 않는다.
`음식/먹는 상황/주요 질감/상태 변화/개인적 먹는 방법/감상의 근거`를 기록한다.

자료 우선순위:
1. 사용자 경험·직접 사진·메모;
2. 실제 식사 후기·일상 관찰의 구체적 먹는 행동;
3. 음식 외형·재료·먹는 방식 확인 자료;
4. 구체적인 음식 행동을 바탕으로 한 창작 재연.

실제 후기, 참고 관찰, 창작 재연을 구분한다.
AI가 직접 먹어본 후기처럼 표기하지 않는다. 인물의 속말은 창작 대사로 명시할 수 있다.
가정마다 달라지는 맛·조합을 음식 전체의 객관적 속성으로 단정하지 않는다.

첨부된 추어탕 잡지 사진은 이번 아이디어의 계기이자 식탁·음식 관찰 자료다.
사진의 문구·편집·로고·사진 자체를 산출물이나 공통 그림체로 복제하지 않는다.
현재 파일은 Git 시각 앵커로 등록하지 않았으며, 첫 에피소드 렌더의 필수 미디어도 아니다.

새 소재를 고를 때 최근 회차의 온도·질감·먹는 행동·감상 어휘가 반복되는지 검토한다.
메뉴 후보를 한꺼번에 전부 제작하지 않는다.

## 6. 말투와 소리

- 음식마다 한두 가지 관찰을 골라 짧게 쓴다. 화면이 이미 설명하는 동작을 매번 중계하지 않는다.
- '위로가 된다', '소확행', '하루의 피로가 녹는다'를 자동 결말로 붙이지 않는다.
- 맛의 정확성보다 과장된 광고 형용사를 앞세우지 않는다.
- 감상은 대사 객체 한 곳에 기록하고 캐러셀/자막/나레이션이 같은 원문을 참조한다.
- 나레이션은 말풍선 속 발화와 구별한다. 속말에는 입모양 동기화를 요구하지 않는다.
- 한입 먹는 순간의 무음·숨·그릇 소리를 남긴다. 계속 떠드는 나레이션이나 큰 씹기 소리를 기본값으로 두지 않는다.
- 기본 음향 우선순위: 필요한 생활 소리 → 짧은 목소리 → 선택적 배경음악.
- 음악은 독립 작곡 프로젝트의 완성을 기다리지 않아도 된다. HB001은 배경음악 없이 설계한다.
- 실제 음성 길이를 확인한 뒤 컷 길이·자막 타이밍을 확정한다. 임시 시간표를 녹음 완료로 기록하지 않는다.

## 7. 시각 방향 — 시안 전 가설

권장 후보는 **단순한 손그림 인물과 배경 + 음식에 집중한 제한적 질감**이다.
음식도 같은 선과 색의 언어를 사용하되, 재료 구분에 필요한 표면 단서를 더할 수 있다.
밥알·국물 표면·바삭한 끝·김의 주름이 검토 대상이다. 광택을 일괄 금지하거나 모든 물체에 추가하지 않는다.
사진 같은 음식에 별개 그림체의 캐릭터를 붙이는 방향은 현재 제안이 아니다.

인물은 첫 파일럿에 1명만 제안한다. 가칭 `diner_01`은 하린 등 기존 주연과 자동으로 동일시하지 않는다.
나이·성별·헤어 등 구체적 정체성은 첫 시안 준비 단계에서 음식/장면에 맞춰 내부 도출하고 기록한다.
별도 캐릭터 시트를 의무 제작하지 않는다. 실제 이야기 첫 컷에서 음식·인물·식탁이 함께 보이도록 검증한다.

표정은 음식의 열감·식감·기호에 맞게 자연스럽게 변화한다.
미소·눈감음·눈썹 변화·짧은 놀람 등은 허용하며, 미리 모두 무표정으로 억제하지 않는다.
레퍼런스의 얼굴 방향을 장면의 카메라 방향으로 복제하지 않는다.
카메라는 음식과 행동을 읽기 위해 고르고, 좌/우/위/아래 시점의 할당량은 만들지 않는다.

참조의 역할은 구분한다:
- `style`: 선·채색·얼굴/음식 표현의 승인 기준;
- `food_content`: 실제 재료·양·형태·조합 참고, 그림체 권한 없음;
- `identity`: 선택한 인물만 통제;
- `continuity`: 식기·음식량·식탁 배치의 연속성;
- `repair_base`: 승인된 구도 중 고칠 부분 외에는 보존.

+- 읽기 쉬운 면 채색과 인물보다 한 단계 낮은 배경 정보량.
+
+집밥에 맞춰 새로 검증할 요소:
+- 음식이 맛있어 보이도록 밥알·노른자·국물·바삭한 표면 등 **재료 구분에 필요한 제한적 질감**을 같은 작화 언어 안에서 어떻게 넣을지;
+- 식기·수저·손·음식의 접촉과 음식량 변화를 자연스럽게 유지할 수 있는지.
+
+제외하는 요소:
+- 참조 이미지 안의 치과 이야기, 대사, 글꼴, 로고/문구, 패널 분할, 인물의 고유 정체성·의상·직업·배경을 복제하지 않는다;
+- 한 파일에 여러 패널을 생성하지 않는다. 집밥은 한 컷 한 파일과 별도 레터링을 유지한다.
+
+이 참조는 음식 실사·메뉴 형태를 통제하지 않는다. 음식 내용은 회차별 food_content 자료와 식사 연속성 계약이 통제한다.
+텍스트 설계를 시각 승인으로 간주하지 않는다.

## 8. 역할과 단계

현재 실행자는 ChatGPT 한 명이며 여러 역할을 순차 수행한다. 별도 에이전트가 실행됐다고 기록하지 않는다.

| 단계 | 역할 | 입력 | 산출물/판정 |
|---|---|---|---|
| P0 시리즈 기획 | 콘텐츠 총괄 | 사용자 목적·기존 공정 | 이 문서, 범위와 성공 기준 |
| P1 음식 조사 | 음식 자료 조사자 | 후보 메뉴·경험·사진 | 출처/관찰 카드, 사실과 창작 분리 |
| P2 감상·비트 | 작가/편집자 | 음식의 구체적 특징 | 감각 변화·짧은 대사 |
| P3 전 컷 설계 | 콘티/연출 | 비트·대사·출력 형식 | 장면·카메라·음식 전후 상태·소리/시간 초안 |
| G0 사전 계획 승인 | 사용자 | P0–P3 패키지와 미확정 항목 | 승인 범위·증거 기록, 변경된 부분만 재검토 |
| P4 생성 준비 | 시각 감독/계약 담당 | 승인 계획·실제 참조 | 스타일/인물/식탁 입력과 렌더 계약, 검증 증거 |
| P5 첫 컷 | 렌더러/QC | 첫 컷만의 계약·실제 미디어 | S01 한 파일, 음식/인물/스타일 검사 |
| G1 첫 컷 승인 | 사용자 | S01 원본 | 시각 방향 기준 확정 |
| P6 나머지 작화 | 렌더러/QC | 승인 기준·각 컷 계약 | S02~마지막 각각 순차 생성·내부 QC |
| G2 전체 작화 승인 | 사용자 | 전체 무문자 개별 컷 세트 | 레터링·후속 영상 작업 진입 |
| P7 합성 | 레터러/편집자 | 승인 그림·대사 | 캐러셀 완성, 선택 시 음성·움직임·영상 |
| G3 최종 검수 | 사용자 | 최종 산출물 | 수정 또는 제작 완료. 게시 승인과는 별개 |
| P8 회고 | 총괄/성과 분석자 | 실제 취향 피드백·있는 경우 게시 성과 | 다음 회차에서 바꿀 점과 보존할 점 |

G0는 현재 초안을 검토하는 지점이다. 음식별 사실 확인이나 미확정 시각 후보는 P4 전 준비에서 보완한다.
이 준비로 메뉴·대사·스타일 방향이 실질적으로 바뀌면 변경분을 제시한다.
G1 이후에는 컷마다 사용자에게 묻지 않는다. 내부 QC 실패는 정상 산출물에서 국소 수정한다.
새 취향 결정이 필요하거나 공통 실패가 반복될 때만 원인을 요약해 사용자에게 돌아온다.
실험 스타일 변경은 임시 적용 → 비교 시안 → 사용자 통과 시 승격, 실패 시 마지막 정상 기준 복구.

이번 요청은 P0–P3 설계까지다. 이미지·음성·음악·영상 생성 호출 및 게시 작업은 포함하지 않는다.

## 9. 식사 연속성과 품질

각 컷에 `food_state_before`, `food_state_after`, `utensil_action`, `camera`, `visible_cast`,
`sensory_job`, `copy_ids`, `sound_cues`를 기록한다.
정지 그림은 한 순간만 보여준다. 전후 상태는 컷을 분할해 그리라는 지시가 아니라 연속성/영상용 정보다.
김·반찬 추가와 음식량 감소가 컷 사이에서 설명 가능해야 한다.

### 계약·기술 오류

- 다른 음식·잘못된 재료·깨진 식기/손·음식과 손의 융합;
- 숟가락/젓가락이 물체를 관통하거나 입으로 이동하며 형태가 바뀜;
- 같은 식사의 음식·식기 위치가 이유 없이 초기화;
- 한 이미지에 여러 컷, 생성 이미지에 읽는 글자 포함;
- 순서 오류, 인물 정체성 이탈, 자막이 음식·손·표정의 핵심을 가림;
- 영상에서 의도하지 않은 형태 변형·루프 이음매·소리와 동작의 불일치.

### 취향·콘텐츠 판단

- 첫 화면에서 메뉴를 알아보고 먹고 싶은가?
- 이 음식만의 감각이 남는가?
- 다음 입에서 변화가 생기는가?
- 감상이 사람이 먹으며 할 만한 말인가?
- 표정과 식탁 분위기가 편안하면서도 심심하지 않은가?

기술 PASS가 취향 PASS를 대신하지 않는다. 예쁜 이미지라도 음식이 안 당기면 스타일 후보를 재검토한다.
코미디·따뜻함·과장의 정도를 하나의 점수로 평균내지 않는다.
QC 기록은 어떤 실제 파일을 누가 확인했는지 attempt_id와 artifact_sha256에 연결한다.

## 10. 데이터·파일 구조와 미래 실행 연결

현재 파일은 세 개만 둔다. 빈 폴더·별도 프롬프트 문서·중복 회차 설명은 미리 만들지 않는다.

| 경로 | 소유 정보 |
|---|---|
| `series/jipbap/README.md` | 시리즈 기획, 공정, 참조 우선순위, QC, 운영 가설 |
| `series/jipbap/STATE.json` | 활성 기획, 승인 증거, 다음 행동, 현재 생성 허가 여부 |
| `series/jipbap/episodes/HB001/EPISODE_DESIGN.json` | 메뉴·소재 근거·대사·컷·시간 초안, 아직 실행 입력 아님 |

실제 생성 단계에서만 회차 폴더에 계약·시도·작화·레터링·영상/음성·출력 자료를 추가한다.
파일 이름은 회차/컷/시도 번호로 구분하고 '최종최종' 식의 복제는 만들지 않는다.
나중의 생성 계약은 입력 문서 버전/해시, 시리즈 ID, 회차 ID, 참조 역할·해시,
renderer/model, 실제 미디어 전달 내역, output path/hash, 승인과 QC 증거를 포함한다.

### 현재 실행기와의 경계

현재 `pipeline/render_guard.py`는 루트 CURRENT_STATE의 `E숫자` 활성 회차와
루트 MASTER_PROMPTS 경로를 전제로 한다. 기존 EPISODE_PLAN 스키마도 `E숫자` 회차를 요구한다.
render/qc Actions는 `episodes/<EID>/` 경로를 사용한다.
따라서 `HB001/EPISODE_DESIGN.json`은 해당 실행기의 입력이 아니며 실행 가능·검증 PASS로 표시하지 않는다.
HB001을 E008로 바꾸거나 루트 Active episode를 갈아끼워 이 제한을 우회하지 않는다.

실제 작화 직전에 연결할 작업:
1. 명시적인 `series_id + episode_id`로 상태·계획·프롬프트·출력 루트를 찾는 resolver 도입;
2. 기존 instatoon 기본 실행을 보존하며 집밥 계획을 실제 계약으로 변환하는 adapter/schema 추가;
3. 시리즈별 스타일 입력·음식 상태·참조 전달·승인 범위 검증;
4. 자동 호출 없는 dry-run으로 HB001이 E007 파일을 읽거나 쓰지 않는지 확인;
5. 준비가 완료된 계약으로만 실제 미디어 생성. 현재는 이 연결이 미구현이다.

이는 후속 구현 계약이지, 이번에 새 플랫폼·DB·큐를 만든다는 뜻이 아니다.
정적 설계 파일은 재개용 입력으로 충분하고, 실행 증거가 생길 때 필요한 필드를 확장한다.
시리즈별 current state는 하나만 유지한다. 향후 회차 production state를 도입하면
기존 STATE의 승인 상세를 옮기고 포인터만 남겨 이중 상태 소유를 피한다.

## 11. 검증 계획과 운영

1. 이번에 시리즈 방향·HB001 콘티·대사를 함께 검토한다.
2. 승인 후 참조와 실행 경계를 준비하고 S01 한 장에서 인물/음식 표현을 확인한다.
3. 통과하면 HB001의 나머지 컷을 내부 QC로 완성해 전체 작화 검수를 받는다.
4. 먼저 캐러셀을 완성한다. 영상 확장은 별도 착수 결정 후 짧은 음성과 필요한 움직임으로 시험한다.
5. 다음 메뉴는 국물류처럼 첫 메뉴와 다른 감각으로 골라 반복 제작 가능성을 본다.

첫 회차에서 보는 것은 '먹고 싶은가 / 다음 컷이 자연스러운가 / 계속 보고 싶은가'다.
게시 실험을 시작하면 캐러셀은 저장·공유·있는 경우 넘김 지표, 영상은 완주·재시청·이탈 구간,
그리고 '무엇이 맛있어 보였는지'의 구체적인 반응을 기록한다.
플랫폼에서 제공하지 않는 지표는 만든 값으로 채우지 않는다. 초기 성과·목표 수치를 발명하지 않는다.

비용은 계획·이미지 시도·음성·영상·편집 시간을 나눠 실측한다.
일정한 컷 수나 생성 성공률·편당 비용을 검증 전 확약하지 않는다.
승인된 이미지의 재사용과 국소 수정을 먼저 검토하고, 먹는 장면의 품질을 희생해 값싼 도구로 강제 전환하지 않는다.
게시 계정·주기·수익화는 시안의 매력을 확인한 다음 정한다. 이번 설계에는 외부 게시나 예약 업로드가 없다.

## 12. 재개와 변경 기록

기존 E007의 승인·시안·대사를 집밥 승인으로 가져오지 않는다.

메뉴·대사·비트 변경 시 영향받는 승인만 갱신한다. 단순 메타데이터 정리로 같은 내용을 재승인시키지 않는다.
